## 2. Notable parameter-level capabilities (from the spec)

These are the rich, easy-to-miss capabilities a caller can drive — catalogued from
the spec so SDK/wrapper coverage can be judged against them.

### Bot avatar — multi-image slideshow (`createBot.bot_image` + `bot_image_config`)
- **`bot_image`** — a single HTTPS URL **or an array of up to 5** (JPEG/PNG/WebP).
  Multiple images are cycled.
- **`bot_image_config.loop_mode`**:
  - `auto` — cycle every `image_duration` seconds.
  - `bot_status` — image 1 on join, 2 when recording, 3 when paused (first 3 only).
- **`bot_image_config.image_duration`** — seconds per image, default 30, range **10–120** (`auto` only).
- Spec ✅ · SDK ✅ (zod + TS) · MCP ✅ — `bot_image` now accepts `string | string[]`
  (max 5) and `bot_image_config { loop_mode, image_duration }` flows through
  `createBot` / `createScheduledBot` / `createCalendarBot` / update shapes.

### Timeout config (`createBot.timeout_config`)
- `waiting_room_timeout` (120–1800s), `silence_timeout`, `no_one_joined_timeout`.
- **`grace_period`** — see §3, **SDK-only / not in preprod spec**.

### Streaming (`streaming_enabled` + `streaming_config`)
- `audio_frequency` ∈ {16000, 24000, 32000, 48000}, `input_url`, `output_url`.
- A single fixed media `input_url` — **not** a swappable/rotating feed.

### Transcription (`transcription_enabled` + `transcription_config`)
- `provider` (`gladia`), `api_key`, `custom_params`.

### Callback (`callback_enabled` + `callback_config`)
- `url`, `secret`, `method` ∈ {POST, PUT}.

### Other
- `recording_mode` ∈ {`audio_only`, `speaker_view`, `gallery_view`}.
- `zoom_config.credential_id` — link a stored Zoom credential.
- **`listBots` filters:** `bot_name`, `participant_name` (case-insensitive partial),
  `bot_id`, `created_before`/`created_after`, `ended_after`, `meeting_url`,
  `meeting_platform`, `status`, `extra`, `limit`, `cursor`. Spec ⟷ SDK: **full parity.**

| 2 | `timeout_config.grace_period` | **absent** (only the 3 timeouts; string count = 0 in whole spec) | **present** in both zod and TS interface | Same skew. Confirm whether `grace_period` is live in the API; if so the **preprod spec is missing it**. |

| 4 | `getScheduledBotDetails` (spec) vs `getScheduledBot` (SDK) | `getScheduledBotDetails` | `getScheduledBot` | Cosmetic naming drift between spec `operationId` and SDK method. Harmless but inconsistent. |

### SDK representation-quality issues (our opinion)

These don't change *what* is exposed but make the SDK awkward to consume — they're
the reason `tools-v2.ts` hand-writes input schemas instead of reusing `V2Zod.*`:

- **Zod ↔ TS type mismatch.** The generated zod schemas use `.nullable()` (infer
  `null`) for optional fields, while the TS interfaces use `?:` (infer `undefined`).
  Passing zod-parsed objects into the typed client therefore type-errors. Documented
  in `api/tools-v2.ts:14-26`. **Ask:** make zod optionals `.optional()` (undefined) to
  match the interfaces, or expose a single source of truth.
- **Enum representation mismatch.** Some zod schemas validate enums as `number`
  while the TS interfaces use literal unions (e.g. `audio_frequency`
  `16000 | 24000 | …`). Forces casts/rewrites.
- **No `CHANGELOG`.** The npm tarball ships no changelog; we had to diff `.d.ts`
  between versions to learn what `6.1.0 → 6.1.4` changed. **Ask:** ship a changelog.
